02 / Design and integration

Offloading decompression from the processor.

JPEG decoding is a natural acceleration target in a camera pipeline: the processor otherwise spends cycles decompressing each frame and writing pixels to memory. I developed a hardware-decoder prototype using UltraEmbedded’s open-source AXI4 JPEG decoder wrapper and its underlying Verilog JPEG core, adapting the integration to our FPGA video pipeline.

Unlike the completed gesture-controlled system’s software decode path, this prototype places the decoder behind AXI4-Lite control registers and gives it an AXI4 memory master for DMA. The archived firmware shows an aligned JPEG buffer, an RGB565 output framebuffer, and VDMA configured for a 16-bit pixel stream. An exported design also contains the RGB565-to-RGB888 converter needed to feed the HDMI path.

Prototype dataflow reconstructed from archived firmware and exported hardware metadata, not a measurement of the final demo.

Firmware-to-accelerator interface

The upstream IP’s control/status interface is mapped at 0x44A30000. The processor programs DMA source/destination addresses, launches a decode, polls the busy flag, and manages cache visibility for DMA. The following pseudocode illustrates the archived integration.

// Hardware-decoder prototype (illustrative pseudocode)
flush_cache(jpeg_buffer, jpeg_length);
write32(JPEG_SRC, jpeg_buffer_address);
write32(JPEG_DST, framebuffer_address);
write32(JPEG_CTRL, START | jpeg_length);
while (read32(JPEG_STATUS) & BUSY) {
    // Wait with a timeout; abort on failure.
}
invalidate_cache(framebuffer_address, framebuffer_size);

Format and clock-domain integration

A 640 × 480 RGB565 framebuffer requires 614,400 bytes and a 1,280-byte row stride, compared with 921,600 bytes for 24-bit pixels. The VDMA and pixel-format converter must agree on the memory layout and stream width. The archive includes hardware exports with the decoder clocked at 25 MHz and 50 MHz, evidence of multiple integration iterations.

Scope of evidence: Seven exported XSA designs include jpeg_decoder_0, and saved firmware identifies the upstream core. The original modified RTL is not present in this archive, and there is no verified end-to-end hardware decoder benchmark here. The final demonstrated system used the software decode path.
