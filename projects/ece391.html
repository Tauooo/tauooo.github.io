How does a bare machine become a system capable of running user programs? In ECE 391, I am working on a teaching operating system that connects low-level hardware interfaces to higher-level abstractions such as threads, files, virtual memory and processes.

Why this project matters

From hardware events to operating-system abstractions.

Unlike application programming, kernel development requires reasoning about the machine itself: what state a processor must preserve, how concurrent work interacts with hardware, and how the OS provides controlled access to memory and devices.

The project brings architecture, systems programming and debugging together in a single environment.

01 / Project scope

What the kernel is intended to support.

The Fall 2026 course spans the following systems topics. These describe the project's educational scope and intended capabilities, not a claim that all of my team's implementations have passed verification.

01 · Device interface

Hardware I/O

UART, real-time clock, platform interrupt controller and virtual devices.

02 · Concurrency

Threads and timing

Context switching, synchronization, scheduling and timers.

03 · Storage

File systems

Block-device interfaces and persistent file access.

04 · Protection

Virtual memory

Page-based address translation and memory protection.

05 · Execution

Processes and system calls

Controlled kernel entry, execution of user programs and process management.

06 · User-facing system

Shell and I/O abstractions

Course topics include user programs, shell operation and pipes.

02 / My development work

Building the foundations, then integrating a kernel.

My work in ECE 391 has included RISC-V assembly graphics, interrupt-driven device interfaces, VirtIO random-number generation and kernel threading. The individual machine problems build the foundations for the collaborative operating-system project.

MP1
Assembly and graphics

RISC-V calling conventions, memory access and framebuffer operations.

MP2
Kernel infrastructure

Device I/O, interrupts, VirtIO and thread synchronization in the individual assignments.

MP3
Unix-like operating system · team project

Integration of memory management, file systems and process execution is part of the collaborative project scope.

I develop and debug in a RISC-V QEMU environment using C, assembly and the GNU toolchain. The focus of this page is the system-level engineering experience; private assignment sources and solution details are not published.

03 / Current status
